01 / Confirmed findings

High priority · Potential edit loss

In-flight autosave can seed a replacement editor with stale text

The final PR commit preserves a draft when an editor closes before its 500 ms debounce expires. The remaining gap begins after the debounce fires: the component marks itself clean, but the shared snippet store is not updated until the asynchronous save returns.

  1. Edit a title or code field and let the 500 ms autosave timer fire.
  2. Keep that save response pending, then switch to a replacement editor for the same snippet.
  3. The replacement initializes with old store values. Edit another field before the first save returns.
  4. The next save sends the old title/code along with the new field, potentially overwriting the earlier edit.

Evidence: a temporary regression probe delayed the mocked API response, remounted the editor, and edited the description. Both the reopened title and the title in the second save were Original Title instead of Latest title. This reproduces the frontend failure; it is not a native SQLite test.

Smallest safe patch scope: preserve the latest draft synchronously across all save entry points—debounce, Ctrl+S and unmount. Prevent an older save result from replacing a newer draft, and retain a retryable draft on failure. Add the delayed-response regression case before changing implementation.

Sources: unmount flush · debounce and immediate save · store response handling

Medium priority · Keyboard navigation

Closing a filtered-out card leaves focus on the page body

Focus restoration searches only for the original card. If an edit removes that card from the active filter, there is no surviving focus target and no fallback.

Reproduced: search for Original Title, open its card, rename it to something that no longer matches, and close the pane. The card disappears and document.activeElement becomes document.body.

Smallest follow-up: focus a surviving card or a toolbar control when the opener is unavailable. Handle disappearance after an asynchronous save as well as during close. Deletion and newly created snippets also deserve missing-opener coverage; those scenarios were not directly reproduced in this review.

Source: card focus restoration.
